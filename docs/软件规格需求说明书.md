## 1. 背景与目标

DSH（DeepSeek Harness）已以 NPM 包形式安装在本机，并自带一套可用的运行配置档与插件机制，以及按通道（alpha，rc）发布的官方更新源。目前这些内容缺少统一的管理入口：用户想确认版本是否最新、弄清它是怎么装上本机的、启停本机的 DSH Web 实例、配置开机自启，都只能手工完成。

DSH Manager 是一个 Windows 桌面应用，用一个界面完成上述四件事。它的边界是：只管理 DSH Web 的**版本、来源、运行、自启**这四件事，不修改 DSH 自身程序，不接管其会话与业务数据，不接触任何凭据类信息，第三方插件的管理交给 DSH 自身能力。

### 1.1 目标

1. 检查 DSH Web 各更新通道的最新版本，并让用户决定自动安装哪个通道的最新版本。
2. 识别本机 DSH Web 是由哪种包管理器（NPM，PNPM，BUN）安装的。
3. 管理 DSH Web 实例的启动与停止，并实时显示其运行输出。
4. 控制 DSH Manager 自身是否开机自启。

### 1.2 非目标

见 §3.2。

## 2. 术语

| 术语       | 含义                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| DSH        | DeepSeek Harness，本机安装的 NPM 包                                                                           |

| Web 形态   | DSH 以浏览器访问方式运行的一种形态                                                                            |
| 运行实例   | 本机正在运行的 DSH 进程；本期的管理范围仅限 Web 形态实例                                                      |

## 3. 范围

### 3.1 范围内

- 本机 DSH 的版本检查、安装包获取与安装，以及自动安装通道的选择。
- 本机 DSH 安装来源的识别与判定依据展示。
- DSH Web 实例的查看、启动与停止，以及运行输出的实时展示。
- DSH Manager 自身的开机自启开关与启动行为设置。

### 3.2 范围外（本期明确不做）

- **第三方插件管理**（浏览运行配置档、插件安装/卸载/更新/启用停用、插件变更备份与回滚、插件操作记录）。本期明确不做，因为用户决定缩减本期范围；插件管理由 DSH 自身能力承担。
- 修改或替换 DSH 自身程序文件。
- 会话、历史、皮肤、宠物、用量等 DSH 业务数据的管理。
- 凭据、密钥、模型配置的查看与管理；不读取、不显示、不上传任何凭据类信息。
- macOS / Linux 支持。
- DSH 其他运行形态的图形化管理：终端形态、无人值守形态，以及桌面端实例的启动与停止。
- 插件市场与插件搜索发现。

## 5. 功能需求

### FR-1 版本检查与通道安装（P0）

- **FR-1.1 通道状态识别（P0）**：必须区分三种状态——已发布、尚未发布、检查失败。尚未发布不算错误，界面应按“未发布”如实展示；检查失败须说明原因，并保留上一次成功检查的结果与时间。
- **FR-1.2 版本信息展示（P0）**：对每个已发布通道展示最新版本号与发布日期，并与本机已安装版本对比，明确给出“有新版本”或“已是最新”的结论。
- **FR-1.3 版本顺序判断（P0）**：必须正确判断预发布版本之间、以及与正式版之间的大小关系。判断错误会直接导致漏报或误报更新。
  - 验收：`0.2.0-rc.2` 比 `0.2.0-rc.1` 新；`0.2.0` 比 `0.2.0-rc.2` 新。
- **FR-1.4 通道选择与自动安装（P0）**：
  - 用户可为**一个**通道开启“自动安装最新版本”，同一时间只允许一个通道处于该状态，切换时需确认。
  - 仅当该通道最新版本高于本机版本时才触发自动安装。
  - 触发后默认仍需用户确认一次；该确认可被用户关闭。
  - 选择结果在应用重启后保持。
- **FR-1.5 安装包获取（P0）**：展示进度与剩余时间；可取消；失败可重试；磁盘空间不足须提前拒绝并提示；获取到的安装包必须做完整性校验，校验不通过**不得**用于安装；传输过程须加密。
- **FR-1.6 安装执行（P0）**：
  - 安装前若检测到 DSH 正在运行，须提示用户先关闭：Web 形态实例可由本工具停止（见 FR-4.3），桌面端实例须用户自行退出；本工具不得强制结束进程。
  - 安装过程须可见（进行中/已完成/已失败）。
  - 安装完成后重新读取本机版本并如实反馈结果。
  - 失败时给出原因与可执行的下一步建议，并保留已获取的安装包，便于用户手工安装。
- **FR-1.7 与 DSH 自身更新行为的关系（P1）**：若 DSH 自身具备自动更新能力，界面须明确提示两者可能互相覆盖，并说明本工具不会修改 DSH 自身的更新设置。
- **FR-1.8 系统代理（P0）**：访问 npm 仓库、更新源等外网地址时，须沿用用户已有的系统代理设置，不要求用户在本工具内重复配置代理。
  - 下列**任一**情形即视为满足要求：① 沿用 Windows 的 WinINET 代理配置；② 沿用 Windows 的 WinHTTP 代理配置；③ 沿用 `HTTPS_PROXY`、`HTTP_PROXY` 环境变量。
  - 代理需要认证时，**不得**读取、显示或保存系统已保存的代理凭据；认证失败须如实说明原因，并提示用户在 Windows 网络设置或环境变量中预先授权。
  - 本工具**只读**系统代理设置，不得修改用户的代理配置。
- **FR-1.9 版本来源范围（P0）**：版本管理只针对 DSH 的 NPM 包 `@deepseek-ai/dsh`，本机版本与通道最新版本均以该包的版本为准。本工具不管理 DSH 运行时组件的版本，两者版本号可能不同，界面须说明本工具所展示的版本属于该 NPM 包。
  - 本机安装方式不属于该 NPM 包时（例如 FR-2.1 判定为官方安装器安装或便携版），须如实说明本工具的版本管理对该安装方式不适用，**不得**猜测、不得给出可能错误的版本对比结论（见 FR-2.3）。

### FR-2 安装来源识别（P0）

- **FR-2.1 结论输出（P0）**：必须给出唯一结论，取值为：包管理器安装（并说明是哪一个）、官方安装器安装、便携版、未识别。
- **FR-2.2 判定依据（P0）**：必须展示得出结论所依据的清单（看到了什么、在哪里看到的），用户可展开查看。
- **FR-2.3 不得猜测（P0）**：依据不足时必须如实输出“未识别”，并说明还缺什么信息，不得给出可能错误的具体结论。
- **FR-2.4 无副作用（P0）**：识别过程不得修改本机任何状态。
- **FR-2.5 及时性（P0）**：识别须在数秒内完成；某一依据来源不可用时应跳过该项，不得导致整体失败或界面长时间无响应。

### FR-3 启动 DSH Web 并显示输出（P0）

- **FR-3.1 启动（P0）**：一键启动 DSH 的 Web 形态；允许用户附加启动参数并选择工作目录。
- **FR-3.2 实时输出（P0）**：运行过程中产生的全部输出（含错误信息）必须实时显示，**不得**等到运行结束后才一次性显示。须提供：时间戳、自动滚动开关、暂停、清空、复制全部、另存为日志文件。
- **FR-3.3 访问地址（P0）**：从输出中识别可访问地址并展示为可点击链接；是否自动打开浏览器须为可设置项。
- **FR-3.4 停止（P0）**：一键停止，须停止完整实例、不留残余进程；应用自身退出时的处理见 FR-4.4。
- **FR-3.5 运行状态（P0）**：展示运行中/已停止、启动时间与运行时长。
- **FR-3.6 失败呈现（P0）**：启动失败（无法启动、立即退出、端口被占用等）时，给出失败原因、最后若干行输出作为上下文，以及可操作建议（更换端口、检查运行配置档等）。

### FR-4 DSH Web 实例管理（P0）

> 本期只管理 Web 形态实例，桌面端实例不纳入管理范围（仅用于安装前提示，见 FR-1.6）。FR-3 描述单个受管实例的启动与输出展示，本条规定跨实例的通用规则；两者表述冲突时以本条为准。

- **FR-4.1 实例查看（P0）**：须列出本机当前正在运行的 Web 形态实例——包括由本工具启动的与用户自行启动的——显示启动时间、运行时长与访问地址（可取得时）。没有实例运行时明确显示“未运行”，不得留空或报错。
- **FR-4.2 启动（P0）**：须能启动 Web 形态实例，启动参数与输出展示见 FR-3。由本工具启动的实例同一时间至多一个；已有实例在运行时再次点击启动，须提示用户先停止现有实例，不得静默另起一个。
- **FR-4.3 停止（P0）**：
  - 停止前须二次确认，并明确指出将影响哪个实例。
  - 须区分“由本工具启动的实例”与“非本工具启动的实例”；后者停止风险更高，须有更强的确认提示。
  - 停止须完整，不留残余进程；停止后界面状态须与实际一致。
- **FR-4.4 应用自身退出时的处理（P0）**：由本工具启动的实例是否随应用退出而停止，须为可设置项（默认停止）；非本工具启动的实例，在任何情况下都不得被本工具自动终止。
- **FR-4.5 失败与无响应（P0）**：启动失败须给出原因与可操作建议；停止超时或实例无响应时，强制终止须单独二次确认，并提示可能丢失正在进行的任务。

### FR-5 开机自启（P0）

- **FR-5.1 开关（P0）**：提供“开机自启”开关，含义是 **DSH Manager 自身随系统登录自动启动**。它不启动 DSH、不修改 DSH 的任何设置，与本机是否安装 DSH 无关。
- **FR-5.2 启动行为（P0）**：可选择启动时“最小化到托盘”或“打开主窗口”，默认最小化到托盘。
- **FR-5.3 状态一致（P0）**：以系统真实状态为准。用户在系统设置中改变状态后，本应用界面须与之保持一致，不得残留错误的开关状态。
- **FR-5.4 关闭即清理（P0）**：用户关闭开关后，须清除开机自启设置，不留残留。
- **FR-5.5 范围（P0）**：本期只支持“登录后启动”，不包含计划任务、延迟启动或后台服务化。

## 6. 非功能需求

| 编号  | 类别     | 要求                                                                                                                       |
| ----- | -------- | -------------------------------------------------------------------------------------------------------------------------- |
| NFR-1 | 易用性   | 界面为简体中文；所有失败给出“原因 + 下一步”；危险操作（安装新版本、停止运行实例）须二次确认                                |
| NFR-2 | 可靠性   | 所有长任务（检查、获取、安装）可取消；取消或失败后不留残缺状态                                                             |
| NFR-3 | 数据安全 | 不上传任何本机数据；不读取、不显示凭据类信息；对 DSH 数据的访问默认只读；系统代理设置为只读，不读取其中的凭据（见 FR-1.8） |
| NFR-4 | 性能     | 版本检查在正常网络下数秒内返回；界面操作不阻塞；运行输出的展示接近实时                                                     |
| NFR-5 | 资源占用 | 日志与输出留存有上限且可配置；空闲时资源占用可忽略                                                                         |
| NFR-6 | 可诊断   | 提供操作记录与诊断信息导出（不含凭据），便于用户反馈问题                                                                   |
| NFR-7 | 降级     | DSH 未安装、结构变化、无网络、代理不可用或代理认证失败时，应用仍可启动并给出明确提示，不崩溃、不自动“修复”                 |
| NFR-8 | 无副作用 | 任何仅用于查看的功能，不得修改本机状态                                                                                     |

## 8. 端到端验收场景
